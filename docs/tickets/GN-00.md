# GN-00: preparar Git e fluxo de revisão

Estado: em avaliação; remoto público criado e PR em preparação. Sem dependências. Não implementar o aplicativo.

## Resultado

Uma `main` com baseline dos dois documentos originais e uma primeira PR contendo as regras e o fluxo de entrega. Isso permite revisar a preparação sem misturá-la ao código Tauri.

## Leia

Leia `../../AGENTS.md`, `../entrega.md` e `README.md`. Confira os limites da especificação nas seções 1, 3, 9 e 15.

## Faça

1. Confirme que está na pasta Git Notch e que não existe repositório ancestral. Se já houver Git, inspecione o estado e adapte sem reinicializar ou sobrescrever histórico.
2. Inicialize com `git init -b main` somente nesta pasta. Verifique a identidade Git já configurada. Se estiver ausente, peça nome/e-mail ao usuário. Não invente identidade nem altere configuração global.
3. Crie o commit inicial contendo apenas `git-notch-spec-v0.1.md` e `git-notch-backlog-v0.1.md`, preservados integralmente. Use staging por caminhos explícitos.
4. Crie `chore/gn-00-repository-rules`. Adicione os arquivos de planejamento e regras preparados nesta pasta. Crie `.gitignore` para `.DS_Store`, `node_modules/`, `dist/`, `target/`, `.env` e `.env.*`, permitindo `.env.example`. Preserve `pnpm-lock.yaml` e `Cargo.lock` no versionamento.
5. Registre o bootstrap em `docs/validation/GN-00.md`, crie `docs/validation.md` como índice desse registro e faça o commit da branch. Não adicione uma licença ao código sem escolha do titular. Não configure CI vazia para produzir checks verdes.
6. Obtenha do usuário o destino do remoto e sua visibilidade se isso ainda não foi informado. Se ele já forneceu um remoto, confirme que corresponde ao projeto. Não reutilize remoto de outro produto.
7. Com autorização para publicação, envie a `main` e a branch. Abra a PR contra `main` com o template. Registre URL e SHA. Não faça merge nem ative auto-merge.

## Aceite e teste do avaliador

- `git rev-parse --show-toplevel` aponta para Git Notch.
- `git show main:git-notch-spec-v0.1.md` e o backlog correspondem aos originais.
- `git diff --stat main...HEAD` contém somente preparação, regras e documentação. Não contém código de aplicativo.
- `git check-ignore .env node_modules/test dist/test target/test` identifica os arquivos gerados como ignorados.
- `git check-ignore pnpm-lock.yaml Cargo.lock` não imprime caminhos e retorna 1 quando ambos não são ignorados.
- `git status --short` não mostra arquivos esquecidos do ticket após o commit. Alterações alheias, se existentes, são identificadas e preservadas.
- A PR permite ler regras, sequência e prompt de delegação. Não há branch protection declarada como ativa sem configuração observada.

## Limites

Sem remoto autorizado, entregue commits locais e instruções pendentes para abrir a PR. Declare GN-00 parcialmente concluído. Não invente URL ou número de PR. Proteção de branch e serviços pagos requerem autorização específica e não bloqueiam a revisão local.
